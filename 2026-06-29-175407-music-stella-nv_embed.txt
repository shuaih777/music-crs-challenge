❯ 为啥Batch size=4都会失败                                                      

● 先看一下训练时的 sequence length 和实际内存分布：

  Searched for 2 patterns, ran 2 shell commands (ctrl+o to expand)

● 找到根本原因了：

  NV-Embed-v2 max_position_embeddings = 32768 tokens

  没有设 max_seq_length，tokenizer 默认用 32768。attention 是
  O(seq_len²)，batch_size=4 × seq_len=32768：

  attention map: 4 × 32 heads × 32768 × 32768 × 2 bytes = 256 GB

  80GB 完全不够。步骤 30 才 OOM 是因为动态
  padding——前几批文本比较短，某批碰到长文本就爆了。

  stella 没问题是因为它只有 400M 参数、seq_len 默认 512。

  Fix：加载 nv_embed 时强制设 max_seq_length：

❯ 你前面说直接在.bashrc里自动恢复是什么意思                                     

● 意思是把恢复命令写进 /root/.bashrc，这样每次容器启动新 shell
  时自动执行，不用手动跑脚本。

  但有个问题：/root/.bashrc 
  本身也在容器上，重启后会消失或恢复成默认。所以这个方案只有在 RunPod
  支持"启动脚本"的情况下才有效——即在 Pod 设置里配置一个启动命令，比如：

  bash /workspace/claude_session/restore_claude.sh

  RunPod 的 Docker Start Command
  字段里填这个，容器每次启动都会自动跑，不需要手动执行任何东西。

  所以实际上有两个选项：

  ┌─────────────┬──────────────────────────────────────────────┬────────────┐
  │    方案     │                   设置方式                   │    效果    │
  ├─────────────┼──────────────────────────────────────────────┼────────────┤
  │ RunPod      │                                              │            │
  │ Docker      │ Pod 设置里填 bash                            │ ✅         │
  │ Start       │ /workspace/claude_session/restore_claude.sh  │ 完全自动   │
  │ Command     │                                              │            │
  ├─────────────┼──────────────────────────────────────────────┼────────────┤
  │ 手动跑脚本  │ 每次重启后执行一次                           │ 手动但简单 │
  └─────────────┴──────────────────────────────────────────────┴────────────┘

  你的 RunPod Pod 设置里有 Docker Start Command 选项吗？
